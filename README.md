# OrgOps oo Action

Run the OrgOps `oo` CLI in GitHub Actions workflows.

This action installs the released Python package that provides `oo`, then runs a
supported command against the checked-out repository.

The default installation path expects the `orgops` package to be available on
PyPI. Until the first real PyPI release exists, use the TestPyPI or
`skip-install` examples below.

## Usage

```yaml
name: OrgOps

on:
  pull_request:
  workflow_dispatch:

jobs:
  topology:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: orgops/oo-action@v1
        with:
          command: topology
          path: .
```

## Commands

The action supports the public `oo` commands intended for CI:

- `topology`
- `team`
- `maturity`
- `validate`

Example validation workflow:

```yaml
jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: orgops/oo-action@v1
        with:
          command: validate
          path: .
```

Example with a pinned package version:

```yaml
- uses: orgops/oo-action@v1
  with:
    command: maturity
    path: .
    oo-version: "1.0.0"
```

Example using TestPyPI before the real PyPI package is published:

```yaml
- uses: orgops/oo-action@v1
  with:
    command: topology
    path: .
    package-index-url: "https://test.pypi.org/simple/"
    extra-index-url: "https://pypi.org/simple/"
```

Example when `oo` is installed earlier in the workflow:

```yaml
- uses: actions/setup-python@v5
  with:
    python-version: "3.12"

- run: python -m pip install /path/to/orgops-package

- uses: orgops/oo-action@v1
  with:
    command: validate
    path: .
    skip-install: "true"
```

Example with additional `oo` arguments:

```yaml
- uses: orgops/oo-action@v1
  with:
    command: topology
    path: .
    args: "--branch main"
```

## Inputs

| Input | Default | Description |
| --- | --- | --- |
| `command` | required | `oo` command to run: `topology`, `team`, `maturity`, or `validate`. |
| `path` | `.` | Repository path or file path passed to the `oo` command. |
| `args` | empty | Additional arguments passed after command and path. |
| `oo-version` | `latest` | Python package version to install. Use `latest` for the newest release. |
| `package-name` | `orgops` | Python package name that provides the `oo` console script. |
| `python-version` | `3.12` | Python version used to install and run `oo`. |
| `package-index-url` | empty | Optional package index URL for pre-release testing. |
| `extra-index-url` | empty | Optional extra Python package index URL. |
| `install-extra-args` | empty | Additional `pip install` flags. |
| `skip-install` | `false` | Skip package installation when `oo` is already available on `PATH`. |

## Outputs

| Output | Description |
| --- | --- |
| `report-path` | Expected report file path generated by commands that write reports. |

Report-producing commands currently map to:

- `topology`: `ORGOPS_TOPOLOGY_REPORT.md`
- `team`: `ORGOPS_TEAM_REPORT.md`
- `maturity`: `ORGOPS_MATURITY_REPORT.md`

## Release

Marketplace releases are created from version tags. The action metadata lives in
the root `action.yml` file so GitHub can publish the repository as a Marketplace
action.
